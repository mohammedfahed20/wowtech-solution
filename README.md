# WowTech Solution Website

A bilingual (Arabic/English), responsive static website for WowTech Solution.

## 1. Project overview

This project is a static website. It does **not** require Node.js, npm, or a database to be served. A Dockerfile is included for deploying it through Coolify on a Hostinger VPS.

The Arabic pages in `ar/` are generated from the English pages. After you change English text, run `python3 scripts/build.py` once (see section 6). Visitors and search engines then get real Arabic HTML at `/ar/`.

Main pages:
- `index.html` — homepage and main service sections.
- `benefits.html` — benefits page.
- `clients.html` — clients and portfolio page.
- `ar/` — the same three pages in Arabic (`/ar/`, `/ar/benefits.html`, `/ar/clients.html`). **Generated by `scripts/build.py`. Do not edit these by hand.**

Supporting files:
- `styles.css` — layout, styling, responsive behavior, and animations.
- `app.js` — navigation, language interaction, visual effects, and contact actions.
- `scripts/translations-ar.js` — Arabic translations (English text → Arabic text).
- `scripts/build.py` — generates the SEO tags, the Arabic pages and `sitemap.xml`.
- `sitemap.xml`, `robots.txt` — for search engines.
- `og-image.png` — the preview image shown when the site is shared (WhatsApp, LinkedIn, X).
- `favicon.ico`, `favicon.svg`, `apple-touch-icon.png`, `icon-192.png`, `icon-512.png`, `site.webmanifest` — site icons.
- `404.html` — page shown for addresses that do not exist.
- `nginx.conf` — Nginx settings used by the Docker image (compression, caching, 404 page).
- `service-images/` — service images.
- `client-logos/` — client logos.
- `wow_it_tag_logo.webp` — company logo used on the pages (`wow_it_tag_logo.png` is the original sheet, kept as a master file).
- `instagram.svg` — Instagram icon.
- `Dockerfile` — serves the static website with Nginx for Coolify deployments.
- `.dockerignore` — excludes Git metadata and documentation from the image.

**Important:** Keep the folder structure and file names unchanged. The HTML pages load assets using relative paths.

## 2. Launch locally (optional)

1. Extract the ZIP archive.
2. Open a terminal in the extracted project folder.
3. Run:

```bash
python3 -m http.server 8080
```

4. Open `http://localhost:8080` in your browser.
5. Press `Ctrl+C` in the terminal to stop the local server.

You can also open `index.html` directly, but using the local server is recommended for testing.

## 3. Publish the website on your domain

### Option A: cPanel hosting (including GoDaddy hosting plans that provide cPanel)

1. Purchase or activate a web-hosting plan and add your domain to it.
2. Open the hosting control panel and launch **File Manager**.
3. Open the document root for your domain. It is commonly `public_html`, but use the exact folder assigned to your domain by the hosting provider.
4. Upload the project ZIP file into that folder.
5. Select the ZIP file and choose **Extract**.
6. Make sure `index.html` is directly inside the domain's document root. For example:

```text
public_html/
  index.html
  benefits.html
  clients.html
  styles.css
  ar/
  app.js
  robots.txt
  sitemap.xml
  site.webmanifest
  404.html
  favicon.ico
  favicon.svg
  og-image.png
  wow_it_tag_logo.webp
  instagram.svg
  service-images/
  client-logos/
```

If extraction creates an extra nested folder, move the contents into the document root. Do not leave the homepage at a path such as `public_html/project-folder/index.html` unless that folder is configured as the domain's document root.

7. In your domain DNS settings, point the domain to the hosting provider using the exact A, AAAA, or CNAME records supplied by that provider. Do not guess record values.
8. Enable the provider's SSL certificate, then visit your domain using `https://`.

### Option B: Static hosting

For Netlify, Cloudflare Pages, or another static hosting provider:

1. Create a new static site/project.
2. Upload or connect the extracted project folder (the folder containing `index.html`).
3. Set the publish/output directory to that folder. No build command is required; leave the build command empty if the provider asks for one.
4. Add your custom domain in the hosting dashboard.
5. Apply the DNS records shown by the provider and enable HTTPS.

### Option C: Coolify on a Hostinger VPS

1. Push the project folder to a GitHub repository.
2. In Coolify, create an application resource and connect the GitHub repository.
3. Select the Dockerfile build method. No build command is needed.
4. Set the exposed/internal port to `80`, add your domain, and enable HTTPS.
5. After deployment, verify both languages, the WhatsApp project form, phone links, and mobile layout.

The project form opens WhatsApp with the visitor's details; it does not save enquiries on the server.

## 6. Updating website content

- Edit English page content in the relevant HTML file (`index.html`, `benefits.html`, `clients.html`).
- If you add or change English text, add or update its Arabic translation in `scripts/translations-ar.js`.
- Page titles and descriptions: edit `<title>`, the `description` meta tag (English), `data-title-ar` on `<html>` and `data-ar-content` on the description tag (Arabic).
- **Then run `python3 scripts/build.py`.** It refreshes the SEO tags, regenerates the pages in `ar/`, rewrites `sitemap.xml`, and checks for broken links. It needs only Python 3 (no installs). Commit the changed files, including `ar/` and `sitemap.xml`.
- Edit colors, spacing, typography, and responsive layout in `styles.css`.
- Keep image filenames and paths unchanged when replacing images, or update the corresponding paths in the HTML files.
- When changing shared content, check all three HTML pages so that the homepage and standalone pages remain consistent.

## 7. Important technical notes

- The service section follows the four reference categories: IT Solutions, Business Technology Infrastructure, Websites, Apps & Software, and Brand & Digital Growth.

- This is a front-end-only static website. It does not include a database, customer login, admin dashboard, server-side form processing, or an order-management system.
- The contact form prepares a WhatsApp message with the visitor’s project details. Enquiries are not stored on the server.
- GSAP, ScrollTrigger, SplitText, and Lenis load from a CDN for the headline, reveal animations, and smooth scrolling. Horizontal client/benefit carousels keep native scrolling. If the CDN is unavailable, the page stays usable and falls back to native scrolling and the existing reveal behavior.
- The previous ChatGPT-hosted preview is separate from this source package. Publishing these files and connecting a domain must be completed through your hosting provider and domain DNS settings.

## 8. Search engine setup (SEO)

The code side is done by `scripts/build.py`. These steps must be done by you, in your own accounts:

1. Add `https://wowtech-solutions.com` to **Google Search Console** (Domain property) and verify it with the DNS record Google gives you.
2. In Search Console, open **Sitemaps** and submit `sitemap.xml`. Then use **URL inspection** on the homepage and `/ar/` and click **Request indexing**.
3. Do the same in **Bing Webmaster Tools** (you can import the site from Google Search Console).
4. Create or complete your **Google Business Profile** for WowTech Solution in Dubai, using the same name and phone number as the website.
5. Make sure the domain redirects `www` to the non-`www` address (or the other way round) and that HTTP redirects to HTTPS, so there is only one version of the site.
6. Re-run `python3 scripts/build.py` after every content change and commit the result.
